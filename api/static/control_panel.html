Send test readings & evaluate

Each reading is a labelled row from the operator-stream fleet (its own seed, never part of the training, validation or test sets) with its true label. The model predicts; we score it right/wrong live. Readings are answered by the cluster API, which logs them: judge them and the verdicts feed the retraining (see the Continuous training tab).

Notifications (Telegram)

Mute or unmute the alert messages sent to Telegram. A mute is an Alertmanager silence: it ends by itself at the chosen time, shows on the Alertmanager page (:9093) with its author, and Prometheus keeps evaluating every alert meanwhile; only the delivery stops. Unmute ends the panel's silences at once.

Fleet

Every machine grouped under the router it depends on, coloured by what the models currently say — the serving pods' own api_currently_anomalous gauge, which is 1 when that machine's most recent prediction was flagged. This is the live model verdict, not a dataset label. Each router card also says what the pattern means, the way network monitoring reasons: dependents that stop reporting (dashed, no report for 2 minutes) are unreachable and point at the router, not at the machines; many dependents degraded together point upstream even when the router's own metrics look normal (a gray failure: silent packet loss the router does not report); a busy router with healthy machines is a control-plane event or a failure still propagating. Measured on realistic data: it names every hard-down router within about 30 s, but catches gray failures only when they are strong (README, section 9c). Machines the pods have never scored are greyed out.

Anomaly history

Past anomaly episodes, from Prometheus: the same verdict as the Telegram list and the Grafana table. By machine sums them up, Episodes lists them; Details shows an episode's times, real labels and every reading.
How this page works
Each machine's verdict is its latest one, from the pod that served it last, among machines that reported in the last 5 minutes. An episode is one stretch of anomalous verdicts; it ends on the first normal one, so a machine flickering around the threshold shows several short episodes. Details opens a window with the episode's times (your time and UTC), the reading time and real label of the readings flagged during it (Demo tab and production agent; kept about 8 hours), the machine's metrics, P(anomaly), IsolationForest score and likely cause around it, and every reading the cluster logged. Times are in your local time, at the resolution shown (15 s up to 41 hours, coarser for 7 days); Prometheus keeps 15 days.

Safety-net experiments (IsolationForest)

Train an IsolationForest for real on a uniform random sample of a dataset, with the production preprocessing (per-machine per-window z-scoring). Each run is compared with the production IsolationForest on the same held-out rows of the independent test set. Nothing here is promoted: the serving model is retrained, guarded and promoted only by the model pipeline (ml-model/train_production.py, Jenkins job devsecmlops-model).

Continuous training

The loop: the cluster logs every prediction, an operator judges some of them (Demo and Operator tabs), the Jenkins job devsecmlops-model exports the judged rows, retrains and lets a guardrail decide, then the model gate and the main pipeline deploy it. This tab only reads: the retraining itself runs in Jenkins.

Review flagged anomalies

Anomalies the pods in the cluster flagged that nobody has judged yet (newest first, from the latest 1000 logged predictions). Logged is when the pod stored the prediction, shown in your local time (the database keeps it in UTC); Reading time is the time of the reading itself; the request to the pod carries only its hour, which picks the time-window baseline. Press Details to open a window with the full picture of a reading (the decision, the metrics, the scores, the history); Esc, the Close button or a click outside closes it. Real label (demo) is the truth for readings sent by the Demo tab or the production agent, which replay labelled data (blank for anything else, and for readings the agent sent before it was restarted). Press Real if the alert was a true anomaly, False alarm if the machine was fine. Verdicts are stored in the cluster database and become training data the next time the devsecmlops-model job runs with feedback.
